발전소 운영 사무를 위탁받은 회사(사무수탁사)들이 보내는 실적 엑셀을 담당자가 하나씩 열어, 날짜 비례 계산(일할 계산)을 하고 시스템에 직접 입력했습니다. 수탁사마다 양식이 달랐고, 일부는 요청해야만 회신을 보냈습니다.

요청

  • 매월 정한 날짜에 요청 메일을 자동 발송하고 미회신 발전소를 따로 추적
  • DB 잠금과 발송 이력으로 같은 달 요청이 두 번 나가지 않게 함

수신과 분류

  • POP3로 회신을 받아 규칙으로 먼저 분류하고, 애매한 경우에만 AI로 보완
  • 메일 서버 인증이 연속으로 실패하면 시도를 멈추고 텔레그램으로 알림

첨부 처리와 적재

  • Excel·PDF·이미지에서 실적을 뽑아 검증한 뒤 적재
  • 수탁사별 양식 규칙을 DB 표에 두어, 양식이 바뀌면 설정만 변경
  • 발전 시작일(상업운전개시일) 기준 일할 계산을 적재 단계에서 처리하고, 같은 자료가 다시 와도 중복 저장하지 않음
  • 파일 단위 롤백, 실패 사유는 엑셀로 내려받기

예외와 검증

  • 분류가 애매하거나 적재 확인에 실패한 건은 검토 목록으로 넘김
  • 운영 전에 같은 메일을 다시 처리해도 결과가 같은지, 저장값이 집계와 맞는지 대조

업무 서버 운영과 백업

업무 시스템 서버의 서비스 운영과 백업 체계

기간
2025.09 ~ 현재
역할
서버 운영, 서비스 추가, 백업 (초기 Linux 세팅은 동료 담당)
기술
Rocky Linux, Nginx, systemd, crontab, firewalld, SELinux, PostgreSQL, restic, Git
  1. 서버 경로·DB 덤프
  2. restic 암호화 증분 백업
  3. 클라우드 저장소
  4. 내려받아 대조
  5. 실패 시 메일

사내 업무 시스템(WEB/WAS·PostgreSQL)과 관제·메일 자동화·내부 도구가 같은 서버에서 돌아갑니다. 초기 세팅 이후의 운영과 서비스 추가, 백업을 맡고 있습니다.

서비스 운영

  • 손으로 띄우던 백엔드를 systemd 서비스로 옮겨 재부팅이나 장애 뒤에도 자동으로 다시 뜨게 함
  • 흩어진 스크립트를 역할별로 옮기면서 하드코딩된 경로와 SELinux 문제를 정리
  • 방화벽 규칙은 실행 설정과 영구 설정이 같은지 확인한 뒤 반영
  • 디스크 사용률이 96%까지 올랐을 때 점유 원인을 운영 데이터·실험 자료·백업으로 나눠 확인하고, 오래된 DB 백업을 정리해 73%로 낮춤

백업 구축

  • 매일 새벽 애플리케이션·홈·설정 경로를 restic으로 암호화해 클라우드 저장소에 증분 백업
  • DB 덤프는 다시 내려받아 원본과 바이트 단위로 비교하고, 실패하면 메일 발송
  • 구축 때 덤프를 새 DB에 복원해 보는 시험

한 달 반 뒤 재점검

  • 야간 실행은 모두 성공으로 남아 있었지만, 스크립트와 문서를 실제 로그·저장소·디스크와 대조
  • 이전 실행이 잠금을 풀지 않은 채 멈추면, 다음 실행이 로그 없이 정상 종료하는 문제 발견
  • 상태 검사가 날짜를 보지 않아 어제 결과를 오늘의 성공으로 표시하는 문제 발견
  • 정리 스크립트가 남은 임시 파일 이름 앞에 매일 '_'를 하나씩 더 붙이는 버그 발견. 이대로면 2027년 3월쯤 파일명 길이 한도에 닿아 Git 미러 백업이 멈춤
  • 알림 상태 파일과 PostgreSQL 설정 파일이 백업에서 빠지는 것을 확인하고, 문제마다 수정안을 정리

2026.09 ~ (v0.2.0, 2026.09)
역할
개인 프로젝트 (기획·개발·배포)
기술
Rust, Windows 네이티브 UI, GitHub Actions
링크
github.com/laekhole/what-am-i-doing

작업마다 Claude Code·Codex 세션을 따로 띄우다 보니, 어느 세션이 끝나서 답을 기다리는지 창을 하나씩 열어 봐야 했습니다. 그래서 세션 상태를 한 창에 모았습니다.

기능

  • 세션별 프로젝트, 마지막 요청, 에이전트, 모델, 상태(내 차례·작업 중·유휴·오류)를 2초마다 갱신
  • 카드를 펼쳐 마지막 요청과 답변, 남은 컨텍스트 확인

동작 방식과 배포

  • 로컬 로그만 읽고 밖으로 보내지 않음. 에이전트를 실행하거나 프롬프트를 보내지 않음
  • 설치가 필요 없는 단일 EXE, 릴리스마다 SHA-256 체크섬과 Sigstore 서명
